# `bsd_*.md` 格式

每个文件是一段改编序列的自包含粗脚本草稿。它要足够支持人工 review 和后续分镜设计，但不是完整 `shot_plan`。

## 必需结构

```markdown
---
片段Id: BSD_1_8_1
剧情概述：一句话说明本片段发生什么、保留什么信息、情绪如何推进。
场景：具体地点（时间/状态，如有必要）。不要写“同前”。
角色：甲、蕾、……
附注：本片段共N句语音。说明关键压缩、转场、资产需求或战斗由用户补充。
关键镜头：N个
剧本：

（关键画面/动作/景别说明）

角色：@vXXXXXXXX 原作台词

音效：SoundEffectName
```

## 文件头规则

- `片段Id` 必须匹配文件意图，例如 `BSD_1_8_1`。
- `剧情概述` 说明改编功能，不写文学气氛。
- `场景` 必须具体且自包含。
- `角色` 列出可见或发声角色；画外/离屏角色在剧本正文中标明。
- `附注` 可写语音数量、压缩方法、转场假设、战斗缺口或素材需求。
- `关键镜头` 是主要视觉 beat 数量估计，不是每句台词都算一个镜头。

## 正文规则

- 对白格式：`角色：@vXXXXXXXX 原作台词`。
- 保留 raw 日文原句；除非控制符影响理解，否则去掉 raw 控制标签。
- 有游戏音效 id 时，用 `音效：...` 标注。
- 视觉说明要克制，主要写关键镜头、表情、站位、转场和停顿。
- 优先使用可见的镜头语言：远景 / 中景 / 近景 / 特写 / 反打 / 插入镜头 / 画外音。
- 根据对白量和自然停顿估算时间；不要在短场景中塞入过多台词。

## 好的视觉说明

```markdown
（中景：甲与蕾隔着诊疗室桌面相对而立。蕾先低头，随后抬眼直视甲）

蕾：@v10100783 （……甲さんの方はどうですか？まだ、何も気にせず、私を信頼してくれますか？）

（甲近景：停顿一拍后点头，视线不躲开）
```

```markdown
（黑屏。远处爆炸声压过上一句尾音，随后切入战斗后的走廊）
音效：Explosion01, AlarmLoop
```

## 不好的视觉说明

```markdown
（甲意识到这句话背后的重量，比任何伤口都更疼）
```

原因：没有直接分镜价值。

```markdown
（沿用前面那个背景，气氛同上）
```

原因：不自包含。

```markdown
（路灯与虚拟草木在校园道两侧延伸）
```

原因：除非素材或游戏背景中确实存在，否则引入了未经确认的画面元素。
