# 改编规则与示例

## 压缩原则

- 只保留承载剧情、人物关系变化、情绪转折或必要转场的台词。
- 合并地点时，必须保证角色留在同一地点继续对话的理由可信。
- 如果转场很别扭，优先使用明确的硬切、黑屏、音效桥或用户确认的跳过，而不是编造尴尬动作。
- 除非吃饭、移动、等待等过场承载关键对白或是最干净的转场，否则应删减。
- 长说明优先压缩为最少量原作台词，只要能支撑后续事件理解即可。

## 路线焦点

- 尊重当前女主路线和情感重心。
- 除非原作存在或剧情必要，不要给配角添加亲密动作。
- 蕾线脚本中，配角可以承担对照、说明或施压功能，但不应抢走甲与蕾的情感高潮。

## 语音与文本

- 只使用 raw 脚本中的原作 voice id 和日文原句。
- 不编造 id，不把改写后的日文当作有声台词。
- 中文只用于场景说明、概述和视觉指导。
- 如果缺失桥段没有合适原作台词，询问用户是否允许无语音字幕/旁白；否则改用非语言转场。

## 视觉指导

应写能帮助后续分镜的信息：

- 有意义的景别和角度；
- 谁在画面内；
- 观众视线如何移动；
- 表情变化；
- 停顿和反应镜头；
- 画外音或音源方向；
- 硬切和音效桥。

避免：

- 画面不可见的内心活动；
- 文学性比喻；
- 只有“悲伤的气氛”但没有可见行为；
- 素材/游戏背景未确认的道具；
- 与分镜无关的 AI 制作约束说明，除非它直接影响镜头安排。

## 示例

### 好：在讨论阶段说明保留台词理由

```text
建议保留 @v10100783，因为它直接把“蕾担心战友信任是否受损”说出口，是本场的情感核心。
建议删去后续重复解释信任关系的旁白，用甲的停顿和 @v10001053 回答承接。
```

### 好：带建议指出制作风险

```text
这里原作同时有诺依、蕾、甲三人对话，并且信息量很密。建议改成诺依先抛出情报，随后用甲/蕾双人反应镜头消化。是否接受把诺依的大段说明压缩到 3-4 句核心语音？
```

### 好：询问战斗缺口

```text
raw 文本没有详细战斗过程，但这一段需要表现“甲和蕾协同突破”。我建议只做：警报响起 → 蕾掩护 → 甲突进 → 敌方崩溃四个关键 beat。你希望这里出现什么敌人/战术，还是先用占位说明？
```

### 弱：抽象问题

```text
你希望剧情优先还是情感优先？
```

替换为：

```text
诊疗室这场可以重点保留两件事：A 甲与蕾修复昨夜后的信任；B 阿南市长情报推进主线。6 分钟版本里我建议 A 用 3 句、B 用 5 句。你是否同意？
```

## 常见反模式

- 写“终幕黑屏+标题卡”，除非用户明确要求后期标记。
- 在 md 文件中写“可复用上半段场景”。
- 原作/背景还是下午，却擅自写成夕暮。
- 添加来源或素材未支持的路灯、草木、人群、武器、车辆等可见元素。
- 给复用语音标注“慌乱地”等不能改变音频、也不指导可见画面的语气说明。
- 每句对白都加注释；只给关键视觉 beat 加注释。
